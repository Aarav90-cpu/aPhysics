Engine Architecture

Planned memory sharing and determinism architecture, plus implemented Phase 1 core utilities.

1. Share Memory Directly with Three.js (Zero-Copy) Planned

Traditional bridges copy arrays between Wasm and JavaScript per frame, increasing copy work and Garbage Collection pressure on large meshes.

Zero-Copy WebAssembly & Three.js Pipeline
// 1. In C: Vertex buffer is contiguous in WebAssembly linear memory
// 2. In JavaScript: Wrap raw memory pointer with Float32Array (ZERO copies)
const positions = new Float32Array(
    wasmMemory.buffer,
    wasmInstance.exports.aphysics_get_positions(),
    vertexCount * 3
);

// 3. Bind directly to Three.js BufferAttribute
geometry.setAttribute('position', new THREE.BufferAttribute(positions, 3));

// 4. On each simulation step in C:
wasmInstance.exports.aphysics_step(dt);
geometry.attributes.position.needsUpdate = true; // WebGL streams directly to GPU VBO!

2. Deterministic Simulation via Seeds Planned

Remotion renders video frames concurrently across worker threads or cloud rendering containers. To keep simulation results consistent between machine A and machine B:

  • Fixed Seed (seed = 1337ULL): Designed so the internal PRNG produces repeatable perturbation values, folding angles, and tear thresholds per run.
  • Pure C Engine: The simulation core never queries system clocks or entropy. Callers or the JavaScript wrapper provide explicit seeds.
  • Decoupled Fixed Delta Time (Δt): The solver advances on fixed intervals (e.g. 1/60s), avoiding frame-rate-dependent step divergence.

Autonomous Agent Rules in AGENTS.md

This repository enforces strict operational guidelines for AI coding agents to guarantee code quality, reproducibility, and safety:

  • Understand & Plan First: Agents must read code and present a detailed plan before making edits.
  • Strict Tooling: Clang 23 only, Bazel 9 only. No GCC, no Makefiles.
